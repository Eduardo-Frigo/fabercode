# Faber Code desktop privacy policy

Effective 24 September 2026. This policy describes the Faber Code desktop
application maintained by Eduardo Frigo. The [project website](https://www.fabercode.site/)
and user-selected services have their own processing practices.

## Information kept on your device

Faber Code stores project files, application settings, provider API keys,
conversation and project context, and local memory data on the device where it
runs. A Faber account is not required. The project maintainer does not operate
a Faber backend that receives this data by default and has no remote access to
your local files through the application.

## Network use you choose

When you configure or invoke an external integration, Faber Code sends the
information needed for that action to the destination you selected. This may
include prompts, relevant project context, API credentials, search terms,
repository data, or tool inputs. Examples include AI providers, Pexels,
GitHub, and external MCP servers. A project's own preview, dependencies, or
terminal commands may also make network requests under that project's control.

You can avoid these transfers by not configuring or invoking the relevant
integration. To stop using an integration, remove its key or connection in the
application settings. The recipient's handling of data is governed by its own
policy. For common integrations, see [OpenAI](https://openai.com/policies/),
[Pexels](https://www.pexels.com/privacy-policy/), and
[GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement).
For any custom provider or MCP server, consult the policy of the endpoint you
configure.

## Retention and contact

Local data remains on your device until you delete it or the application's
data directory. Uninstalling the desktop application may leave this user data
behind. The project maintainer cannot delete data held by an external provider;
contact that provider for its retention and deletion process. Questions about
this policy can be raised through the repository's
[GitHub Issues](https://github.com/Eduardo-Frigo/fabercode/issues) without
posting private data.
